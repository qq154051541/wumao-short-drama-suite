# AI 短剧全流程 Asset-First 六阶段生产管线 (Asset-First Pipeline)

> ⭐ **全局总控流程（★权威）**：本文件定义本 skill 从立项到成片的**唯一生产顺序**。所有模块（剧本/资产/分镜/渲染/质检）都挂载在这六阶段上，禁止跳步。
>
> ⚠️ **两条正交轴，别混谈**：本文件管 **A 轴（任务复杂度 → 走不走资产链）**；**图在不在手里（M0/M1/M2 素材形态）** 由 `asset-delivery-modes.md`（★权威）管——**两者正交**，A 轴判不清按 A3 处理，**M 轴按用户实际条件处理，不取最高档**。
>
> 🔗 联动：**素材形态与门禁改判 → `asset-delivery-modes.md`（★权威，本文件所有门禁的判定细则以它为准）**；画幅/风格/平台锁定 → `aspect-ratio-adaptation.md`；剧本门控 → `screenplay-gate-engine.md`；资产图执行 → `asset-spatial-ledger.md` / `character-lineage-and-sheets.md` / `production-ledger-handbook.md`；分镜 → `blocking-direction.md` / `spatial-topview-camera.md` / `sd-combat-engine`；渲染 → `seedance-render-engine.md` / `model-adapters.md`；质检 → `quality-gate-review.md`。

## 〇、 核心原则（铁律）

1. **生产顺序先于一切**：P0 立项锁定 → P1 剧本门控 → P2 数字资产包 → P3 空间调度+分镜 → P4 投喂稿文本装配 → P5 出稿质检 → 每项目导演台审阅 → 明确出片授权 → 实际生成 → 成片另验，**禁止跳步、禁止倒序**；
2. **默认交付提示词/文档；实际生成遵循已有授权范围**：未获生成授权时不调用图片或视频生成工具。用户明确授权资产生成后，优先本地能力，按授权的素材、批次及数量执行，**不重复逐张索权**；仍保留门禁 1 清单确认与门禁 2 逐批锁定，不把确认当作新的生成授权。**保存、签审不生成；资产生成授权不等于出片授权**，成片须导演台审阅并获明确出片授权后执行；
3. **图在哪儿，决定门禁怎么判（与第 2 条配对）**：本包默认不要求持图或交回图。合格形态分三级：**M0 纯提示词**（不写图号）/ **M1 编号占位**（写 `图N` + 必附《素材接线单》，**默认**）/ **M2 已入库**（用户提供或授权本地生成的实际素材已可访问并登记）。**M2 不等于授权、锁定或已视觉核验**，各状态分别记录。每次交付首行声明当前形态，细则见 `asset-delivery-modes.md`（★权威）；
4. **"名字+装扮"是否算资产，按形态定**：**M2** 下资产 = 可直接投喂的资产参考图（角色 4 View / 场景资产图 / 道具图），文字描述只是索引标签；**M1** 下资产 = **编号 + 用途 + 外观要素档案 + 接线单一行**；**M0** 下资产 = **外观档案复述块本身**（文字即资产）。**三种形态都算"有资产"，不存在"M0 就等于没资产"**；
5. **无图不进分镜 → 改判为条件门**：分镜引用的锚点必须有**对应物**，但"对应物"按形态定义——M2 指向已锁定资产图；**M1 指向已登记的图号（在接线单/素材映射表内）**；**M0 指向已写出的文字档案**。**缺图不阻断文本编排**；M2 待锁定项可注明文字/编号依据继续编排，但实际生成缺必需素材或锁定条件时必须阻断生成；
6. **不索要 · 不阻塞 · 不假装 · 要声明**：不以交回图片作为文本编排的条件；缺图不阻断分镜、投喂稿装配与出稿质检，实际生成缺必需素材必须阻断并列明缺项；**禁止写不存在的图号、禁止未实际查看却声称已视觉核验**。详见 `asset-delivery-modes.md` §五；
7. **画幅、风格、平台在 P0 一次锁定**，全流程沿用；**中文短剧 B=9:16 已确认，回显即可，不重复询问**（资产板自身画幅仍按专业模板，见 `aspect-ratio-adaptation.md`）。每项目接入独立导演台，P0 执行导演台安装 check 并登记接入状态；检查失败列明问题，不冒称已安装或已审阅；
8. **分批出图 + 逐批确认**（**仅用户下发出图口令后适用**）：资产不一次性堆砌，按 角色→场景→道具 分批产出，每批锁定后才进下一批；
9. **资产依赖分级（A0~A3 · A 轴）**：Asset-First 能力全保留，但按任务复杂度触发——**A0** 纯文字/单镜/无角色一致性要求：不强制资产链，文字描述可直投（禁用图号即不受门禁 3/4 约束）；**A1** 单角色单镜：资产可选（有参考图更稳）；**A2** 跨镜角色/场景一致性：启用相关角色/场景资产；**A3** 多人/多场景/连续剧集/高一致性项目：完整执行六阶段（默认档）。**判定不清按 A3 处理（宁全勿缺）**。

## 一、 六阶段总览

```text
P0 立项锁定（中文短剧 B=9:16 已确认回显 / 风格 / 平台 / 时长）+ 每项目导演台接入与安装 check + ★素材形态初判（默认 M1）
  ↓
P1 剧本五阶门控（前提 → 结构 → 节拍 → 实体 → 专业剧本页）
  ↓
P2 【数字资产包】（本 skill 核心阶段 · 按 M 形态分流）
  ├─ 2a 实体提取：从剧本自动提取全部 角色(CHR)/场景(SCN)/道具(PRP)/声音(AUD)
  ├─ 2b 资产清单：全量编码 + 16项五官 + 6项材质 + 亲缘推导表(T1→T2→T3) + 用户确认无遗漏
  ├─ 2c 出图/出词（★按形态分流）
  │     M0 → 产出「外观档案复述块」供各段复用（不写图号）
  │     M1 → 产出「出图提示词 + 图号编号 + 《素材接线单》」（默认；可外部跑图）
  │     M2 → 核实并登记实际素材；缺项仅在已有生成授权范围内优先本地补齐：①角色 4 View ②场景 ③道具，每批确认锁定
  └─ 2d 交付《资产图册》（★按形态降级）
        M0 → 《外观档案册》（无图，纯文字档案）
        M1 → 《资产编号册 + 素材接线单》（编号 + 用途 + 外观要素 + 该挂哪张）
        M2 → 《资产图册》（附资产参考图，单一事实源）
  ↓
P3 空间调度 + 分镜（锚点按形态指向：M0 文字档案 / M1 已登记图号 / M2 已锁定资产图；CAM1~4 / 180°轴线）
  ↓
P4 投喂稿文本装配（沿用 A 锁：Seedance 2.5 / 2.0 按 model-adapters.md 契约装配，MiniMax-H3 按 h3-adapter.md 独立字段装配；时长按所选模型契约，不实际生成）
  ↓
P5 出稿质检（P0/P1/P2 + 文本/编号一致性；M2 仅在具备视觉能力且实际查看后另记图像核验；修改稿须三步复验并附《改动复验报告》，见门禁 6）
  ↓
项目导演台审阅（保存、签审均不生成）→ 明确出片授权 → 必需素材检查 → 实际生成 → 成片另验
```

## 二、 P2 数字资产包执行细则

### 2a 实体提取（从剧本自动派生）
- 扫描定稿剧本，提取全部**有跨镜复用**的实体：
  - 角色 CHR：A（核心）/ B（常驻）/ C（群众，仅需文字描述）；
  - 场景 SCN：核心场景（多集出现 / 关键打斗 / 重场戏）必须建档；一次性过场场景可仅文字；
  - 道具 PRP：剧情关键物证 / 多镜出现 / 有防穿模风险的道具必须建档；
  - 声音 AUD：OS / 对白 / SFX / BGM 四类，进产出册声音资产表。
- **判定标准**：该实体是否在 2 个以上镜头/场景出现，或在后续剧情中复用 → 是则建档（**M0 建文字档 / M1 建编号档 / M2 建图档**）。

### 2b 建档清单（用户确认门禁 1）
- 输出《完整资产清单》：所有实体编码 + 角色 16 项五官 + 6 项材质 + 亲缘推导表（T1→T2→T3 骨相继承 40%~60%）+ 场景空间属性 + 道具特征；
- **M1/M2 须确认清单"无遗漏、无错位"后进入 2c；M0 文字档案确认可选、不阻塞**，以 `asset-delivery-modes.md` 门禁 1 为准；
- **本步不要求图片**：清单是文字/编号层确认；实际资产生成前仍须清单确认及对应生成授权，不将清单确认视为授权。

### 2c 出图 / 出词（按 M 形态分流 · 每批确认门禁 2）

| 形态 | 本步产出 | 门禁 2 判定 |
|---|---|---|
| **M0** | **外观档案复述块**（发/服装/体态/年龄感/标志物五要素，供各段直接复用）+ 场景坐标系与 `SET_STATE` 登记 | 复述块是否**五要素齐全**（缺项 → 回补） |
| **M1**（默认） | **出图提示词**（可外部跑图）+ **图号编号** + **《素材接线单》** | 每个图号是否有接线单行 + "只控制什么/不控制什么"是否写全 |
| **M2** | 实际角色（A/B 级 4 View 资产板）/场景/道具素材登记；生成缺项须有对应授权，优先本地，按已有范围分批执行并确认锁定 | 登记、授权、逐批锁定和视觉核验分别记录；不得由 M2 自动推定任一状态 |

> **M0 / M1 默认只编排文本，不自动分批出图**；若用户授权生成，按授权范围优先本地执行，实际素材登记后转 M2。**禁止以缺图或资产图未锁定为由卡住 P3 文本编排**；实际生成缺必需素材或锁定条件时，必须阻断生成。

### 2d 交付台账（★按形态降级命名，禁止混称）
- **M0** → 产 `《[剧名]_外观档案册.md`：每条 CHR / SCN / PRP 附**外观档案复述块 + 场景坐标系 + 状态变体**，**不含任何图号**；
- **M1**（默认）→ 产 `《[剧名]_资产编号册.md` + 《素材接线单`：每条附**编号 + 用途 + 外观要素 + 该挂哪张 + 只控制什么/不控制什么**；**接线单是交付必备件**；
- **M2** → 产 `《[剧名]_资产图册.md`：CHR / SCN / PRP 全部附**资产参考图** + 短锚点，成为 P3/P4 唯一权威事实来源（Single Source of Truth）；
- **三种交付物共同点**：都是 P3/P4 的权威依据——**"有依据"不等于"必须是有图的依据"**。命名**不得混称**（M0/M1 稿里写成《资产图册》即为形态违约）。

## 三、 门禁与确认点

> ⚠️ **门禁按素材形态改判**：下表是**速查版**；**逐形态的完整判定细则以 `asset-delivery-modes.md` §二 为准**（本表与它冲突时以它为准）。

| 门禁 | 位置 | 规则（速查） | 形态影响 |
|---|---|---|---|
| **门禁 1** | P2b → P2c | 建档清单确认按形态执行；实际资产生成前必须确认 | M0 文字档案确认可选、不阻塞；M1/M2 清单确认不要求交回图片，确认不等于生成授权 |
| **门禁 2** | P2c → P3 | 核查本批产出及确认状态 | M0/M1 核查复述块/接线单齐全；M2 逐批确认后标锁定，待确认项注明文字/编号依据，缺图不阻断文本编排 |
| **门禁 3** | P3 | 分镜锚点无对应物 → 阻断并回补 | **对应物按形态定义**：M0 文字档案 / M1 已登记图号 / M2 已锁定资产图 |
| **门禁 4** | P4 | 投喂稿锚点与映射不一致 → 阻断 | M0 无图号；M1 图号槽位须与接线单**逐条对应**；M2 原样 |
| **门禁 5** | P5 出稿质检 | 一致性不符 → P0 阻断出稿 | M0/M1 与文字档案及编号一致；M2 登记不等于视觉核验，仅在具备视觉能力且实际查看后记录图像级结果，否则标未视觉核验 |
| **门禁 6** | P5（修改类交付） | 修改稿未跑「局部验证 → 联动冲突检查 → 全量审核」三步复验 / 未附《改动复验报告》 → 阻断交付（见 `quality-gate-review.md` §三） | **不受形态影响，始终全量适用** |

**形态声明为交付前置**：交付稿**首行未声明素材形态（M0/M1/M2）** → 视为形态未定，机检告警（`sd-feed-engine/scripts/gate_check.py` 闸门 6），**不得交付**。

## 四、 与其他模块联动
