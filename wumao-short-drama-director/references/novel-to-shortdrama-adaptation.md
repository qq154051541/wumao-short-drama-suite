## 一、 剧情理解三层（先读懂，再动刀）

> 铁律：**⛔ 禁止把整本小说一次性塞进上下文后直接"写剧本"**。GitHub 上 21.8k★ 的 Toonflow 用「章节事件图谱 + 本地向量记忆」解决同一问题；本包等价做法是**先落三张结构化账，再按事件精准调用**。这也符合本包 `slice_context.py` 的「只读切片」纪律与预算铁律。

### 1.1 第一层 · 事件图谱（不是事件流水账）

在 `story-bible-and-ip.md` §2.3 已有的 `EVT-####` 基础上，**补因果边与可见性**，每条至少七列：

| 列 | 写什么 | 为什么需要 |
|---|---|---|
| `EVT-####` | 稳定编号（沿用本包口径） | 下游爽点表 / 钩子账 / 分集卡引用 |
| 前提 → 触发 → 动作 → 反制 → 结果 | 沿用 `story-bible-and-ip.md:460-464` | 保真 |
| **因果边** | `前置事件 ID` / `解锁哪个后果` / `被哪个伏笔回收` | 判断「砍掉这段会不会断链」——这是删线的唯一依据 |
| **信息可见范围** | 观众知道 / 主角知道 / 反派知道 / 只有读者知道 | 短剧靠信息差制造爽感，不标注就无法设计「亮牌」 |
| **状态变化** | 权力 / 知识 / 关系 / 风险 / 物理状态，哪一项发生了**不可逆改变** | `episode-planning.md:33-42` 的分集单位就是不可逆状态变化 |
| 场景与在场人 | 谁必须在场（见证者） | §三「见证」要件的前置 |
| 原著位置 | 卷 / 章 / 段号 | 可追溯，改坏了能回查 |

### 1.2 第二层 · 人物关系图谱（全书级，不是逐集）

`episode-planning.md:150-160` 已有**逐集**人物关系矩阵；本层补**全书一张**，关系对至少五列：
`关系 / 利害 / 亲疏 / 权力方向 / 欠与债`（沿用本包既有字段），并**额外补三列**：`公开身份 vs 真实身份` / `误信或承诺` / `关系可逆位移点`。

- 用途：找「身份揭露」「扮猪吃虎」「最信任的人背叛」这类爽点的**结构前提**；
- ⛔ 一人一实体：无法确定两个称谓是否同一人时**分开建两条**，不合并（合并错了，之后每条关于「他」的事实都可能属于另一个人，且文本里几乎看不出来）。

### 1.3 第三层 · 多线时间线账本

`SERIES_SCRIPT_STRATEGY`（`six-stage-pipeline.md:170`）只有「主线/情感线/成长线/关系线/谜团线优先级」的文字锁。本层把它落成**逐线一行**的可机读账：`线名 / 起点事件 / 关键节点 / 兑现事件 / 与哪条线交叉 / 是否可压缩 / 是否可前置`。

### 1.4 改编值四问（决定「值不值得改、改哪本」）

来自番茄小说改编侧公开口径（强 / 快 / 画 / 钩），落成四问，**答不上来就别急着动刀**：

1. **强**：核心冲突能不能一句话讲清？（复仇 / 逆袭 / 守城 / 查案……）讲不清 = 观众三分钟进不去；
2. **快**：原著每一章，读者是想翻下一页还是想关掉？**连续 3 章以上没有情绪触动点的长段**，就是改编时要合并或砍掉的段落；
3. **画**：场景能不能画出来？写「刀尖离喉咙还有一寸」，不写「气氛很紧张」；写「攥着的茶杯裂了条缝」，不写「他很生气」。**氛围描写必须翻译成可见动作**（例：小说开头「煮咖啡看窗外下雨」→ 短剧「咖啡泼在渣男衬衫上」）；
4. **钩**：每章结尾有没有「欲知后事」的那口气？没有的段落不承担留存功能。

### 1.5 来源三分法（防「理解」变成幻觉）

沿用本机 `wumao-short-play` 战术 32，所有改编动作必须标来源级别：

| 级别 | 定义 | 允许做什么 |
|---|---|---|
| **原话** | 原著明确写出 | 直接进分镜，只换镜头语言，⛔ 不换事实 |
| **模式** | 全文观察到的重复规律（爽点结构 / 人物反应方式 / 节奏偏好） | 可据此补一句台词或一个反应，**必须标注来源段号** |
| **假设** | 既不在原文也不是既有模式的改编新增 | 必须标置信度（低/中/高）并进待验证清单；**置信度低且成本高者不进生成层** |

> ⛔ **禁止把「模式」升格成「原话」**，也禁止把 T2 讨论当事实设定（`SKILL.md` 〇·1 与套装共享契约第 9 条）。

## 二、 爽点表驱动的主动取舍（转化，不是压缩）

> 本包七类改编决策是「保真 + 删减审计」，这里补的是**正向的短剧化取舍**。核心判据一句话：**原著的叙述顺序是给读者的，短剧观众为爽点停留；不先给爽点排名，就会按时序一章一章切，全书最强的高光被推到好几集之后。**

### 2.1 第一步：先排爽点表 `PAY-<N>`（在切候选集之前）

每行一个爽点，**按本书内部相对收益强度从高到低排**（不跨书比较、⛔ 不给虚构分数）：

| 列 | 写什么 |
|---|---|
| `PAY-<N>` | 稳定编号，供分集卡与钩子账引用 |
| 位置 | 章（`sequence`）与情节点，必须回指得到；回指不到的条目删掉 |
| 类型 | 打脸 / 奇观 / 反转 / 身份揭露 / 奖励兑现 / 危机，可多选 |
| **谁兑现** | 主角、对手、**旁观者或群体**——群里改口、围观者集体道歉、老前辈当众表态，收益都落在主角身上，⛔ 别漏 |
| 收益落在谁身上 | 被打脸的是谁、**他之前压迫得多具体**（压迫越具体，落差越大） |
| **首集能力** | 这一处能否同时交代主角身份 + 眼前危机 + 目标？能的标出来，它是**开篇替换点候选** |
| 依赖 | 观众要先知道什么才看得懂；能否在开场后补 |

> 「长间隔说明」：连续 3 章以上没有触动点时，写清原著靠什么维持期待——**改编时这些间隔就是首要合并/删除对象**。

### 2.2 第二步：压缩两步走（顺序不能反）

1. **先留高热爽点**：只保留爽点表里排名靠前的情节点（爽点 / 糖点 / 虐点）；
2. **再删线、后合并**：
   - **先删线**：整条支线删掉；
   - **后合并**：把功能重新分配给留下的人物。
   - ⛔ 顺序反了会白做——如果刚分配完功能的那个人所在支线随后被删，分配全部作废，且往往已经带着它改过分集地图。
3. **合并功能重复的人物**（例：三个配角合成一个「功能性反派」，专责每集制造麻烦）。人物少了，冲突密度反而上去。

### 2.3 第三步：集数跟爽点走

- ⛔ **禁止按章 1:1 切集**（结果通常是拉长而非压缩，第一个爽点被推到好几集之后）；
- 没有爽点的长段 → 并进相邻集或删；一章里有两个大爽点 → 可拆两集；**后文高光可以提前**；
- 「开篇替换点」：优先用 `首集能力 = 能` 的那个爽点替换原著慢热的开篇（对应红果/番茄「前 3 秒 / 前 3 行」口径）；
- **人物配额**（外部方案的常见做法，**经验值·待实测，非本包硬指标**）：核心人物 3~5 人、全剧 ≤20 人、高潮集新增人物 ≤2 个。写进产物时标注「经验值」，⛔ 不得当机检门。

### 2.4 与六阶段链的接线（不新增阶段）

| 六阶段 | 本文件插入什么 | 落到哪个既有交付件 |
|---|---|---|
| ① 来源登记 | 长篇分块时同步标 `原话/模式/假设` | `SOURCE_MANIFEST.json` / 事实账本 |
| ② IP 与角色开发 | **事件图谱 + 关系图谱 + 多线时间线**三张账 | `01_ip/` 下新增三张账（不改六件套清单，作为 `IP_BIBLE` 附件） |
| ③ 全剧开发圣经 | **爽点表 PAY-N + 改编值四问 + 主动取舍决策**（`REORDER` 从「候选」升级为「已裁决」，须记录前置了哪个高光、为什么） | `ADAPTATION_BLUEPRINT.md`（原有交付件）扩写，钩子仍**不分配到具体集**（遵守 `story-bible-and-ip.md:444`） |
| ④ 分集规划 | **每集钩子矩阵**（§四）喂给 `RETENTION_CONTRACT` / `VIEWER_RETENTION_MAP` / `HOOK_PAYOFF_LEDGER` | `03_episodes/` 既有六件套 |
| ⑤ 正式剧本 | 爽点五要件验收（§三） | `EDITORIAL_REVIEW.md` 审稿层 |
| ⑥ 圆桌 | `payoff_satisfaction` 评分项现在有可核对的五要件 | `roundtable-review.md:185` |

## 三、 爽点工程（让爽点直击人心）

### 3.1 爽点五要件（补上包内「准备、见证、结果」那句单句规则）

任何标为 `PAY-<N>` 的爽点，**五格缺一即判为「伪爽点」**，必须补齐或降级为普通情节点：

| # | 要件 | 落地判据 | 缺了会怎样 |
|---|---|---|---|
| 1 | **准备** | 前置证据已入事件图谱、观众看得懂（对应 `依赖` 列）；反派的压迫/嘲讽有**具体形式** | 打脸变成突兀的吵架 |
| 2 | **压制** | 主角先吃亏、被低估、被公开羞辱，且**有画面证据**（不是旁白说） | 没有落差，爽不起来 |
| 3 | **见证** | 现场有具名见证者 / 围观群体；**公开场合优先**（私下被羞辱的打脸爽感远不如当众） | 赢了没人看见 = 不爽 |
| 4 | **兑现** | 干净利落的**具体动作或物证亮牌**，有具体的颜面损失（被下属目睹 / 经济损失 / 身份反转） | 变成嘴炮胜利 |
| 5 | **后果** | 关系 / 权力 / 地位发生**不可逆位移**，并写清谁承担代价 | 爽完即忘，下一集归零 |

> 与本包既有禁令对齐：`FORBIDDEN_CHANGE`「为制造爽点让人物违背锁定 IP 且不承担后果」（`story-bible-and-ip.md:691`）正是要件 5 的反向约束；`six-stage-pipeline.md:203`「反派为送爽点公开自毁」正是要件 1 的反例。

### 3.2 爽点六格矩阵（每集门禁，缺一格写「待验证」）

归纳自本机 `wumao-short-play` 战术 36。**⛔ 任何一格缺证据必须写「待验证」，不得为了填满结构而推断**：

| 格 | 必答问题 | 不成立的样子 |
|---|---|---|
| 身份反差 | 观众第一眼觉得主角是什么人？与旧模板差在哪？ | 写出来仍像任何一部霸总剧 |
| 情绪共鸣 | 哪一秒观众觉得「我懂他」？**是哪个动作而不是哪句台词**？ | 只有打脸没有委屈，只有赢没有代价 |
| 能力展示 | 主角用哪个具体动作 / 哪句话证明他早就看穿了？ | 全靠对手降智来证明主角聪明 |
| 外部压力 | 谁在施压、施压的具体形式是什么？ | 压力只靠旁白说，没有画面证据 |
| 关系绑定 | 这一集哪两个人的关系发生了**不可逆位移**？ | 人物只是同处一室，关系没变 |
| 可持续冲突 | 结尾留下的问题，下一集必须用**新信息**才能解决吗？ | 钩子只是氛围悬念，没有具体待解问题 |

### 3.3 爽感类型学与配比

**8 类爽感**（外部 `0xsline/short-drama` 口径）：打脸 / 逆袭 / 甜宠 / 虐心 / 悬疑 / 燃 / 搞笑 / 感动。
**9 类反转轮换**（外部 `short-drama-factory` A~I 口径）：相邻 **3 集禁复用**同一类，与本包 `episode-planning.md`「无连续三集同公式」一致，可合流。

四类主力爽感的正向写法（公开爆款拆解口径，**经验值·非实测**）：

| 类型 | 关键不在哪 | 必须写什么 |
|---|---|---|
| **复仇 / 打脸** | 不在打脸动作，**在「被打脸者的反应」** | 反派嘲讽压到足够强度 → 反击干净利落不留余地 → **具体的颜面损失**：公开场合 / 被下属目睹 / 经济损失 |
| **逆袭 / 扮猪吃虎** | 不在「主角变强了」 | 每一次提升**看得见**（能力/财富/地位的具体变化）+ **对照组**（其他人对他态度的变化） |
| **甜宠** | 不在一直甜 | **甜 → 虐 → 甜**；有效甜点：保护性动作 / 公开承认关系 / 无言支持（送伞、递热水） |
| **身份揭露** | 不在揭晓那一刻 | 提前埋「藏锋」细节（按灭手机继续端洗脚水），让观众先于剧中人知道 = 期待感 |

### 3.4 爽点密度门（**经验值·待实测**，明确标注）

本包此前**零爽点密度字段**（`episode-planning.md` 只有「15 秒段 ≥1 情节点 / 单集 ≥5 情节点」）。补一条**软门**，产物里必须标「经验值」：

- 每集 **≥1 个主爽点**（五要件齐）+ **≥1 个小爽点**（小反转 / 底牌一角 / 一句回怼）；
- **每 20~30 秒一个情绪节点**（台词冲突 / 动作冲突 / 信息冲突，任一即可），压→爆→压→爆；
- **相邻 3 集主爽点类型不重复**；
- 每 3~5 集一个大爽点，⛔ 禁止把最大的揭穿留到很后面；
- ⚠️ 本包 `SKILL.md` 法则 20·★ 仍是上位：**剧情该慢的段落（静场对峙/宣判/留白/独白）不套密度门**，但须显式标注段落意图；⛔ 也不得滥用豁免把整集写成「展示段」。

## 四、 每集钩子矩阵与卡点位

### 4.1 前 3 秒三型（红果免费短剧公开口径）

| 型 | 写法 | 反例 |
|---|---|---|
| 直接冲突 | 打脸 / 背叛 / 遇险 / 对峙，离婚协议甩脸上、耳光响彻全场 | — |
| 强悬念 | 「你敢动我试试？」/ DNA 报告掉地 / 神秘来电 | 空洞氛围悬念 |
| 极致反差 | 上一秒天堂下一秒地狱：婚礼变葬礼、豪门变弃妇 | — |

⛔ **错误示范**：「清晨，阳光洒进房间，女主慢慢醒来……」；本包 `SKILL.md` 法则 17 已规定**钩子前置 00:00-00:05 首镜**，两者一致。

**0~10 秒三件事**（外部口径，经验值）：抛出核心冲突 / 交代人物关系 / 亮明主角目标。**不需要解释「为什么」，只让观众知道「发生了什么」**。背景在对话里自然透露，⛔ 禁前 30 秒介绍家庭背景。

### 4.2 每集三件套与结尾钩子

- **三件套** = 新冲突 + 旧伏笔 + 情绪爆点，确保每集有信息增量；每集形成「冲突解决 → 新悬念产生」闭环；
- **结尾钩子**必须指向明确：未完成目标 / 突发危机 / 身份反转，直接关联下一集核心内容，⛔ 禁空洞悬念；**永远不要在完整解决问题后结束一集**；
- 与既有 `RETENTION_CONTRACT`（`episode-planning.md:595-604`）绑定：`primary_hook_id` 指向本矩阵行号，`payoff_episode` 指向兑现集。

### 4.3 每集钩子矩阵（本包此前零命中，本文件补的交叉表）

一集一行，**七列**；这张表是 `VIEWER_RETENTION_MAP` 与 `HOOK_PAYOFF_LEDGER` 的上游输入，不替代二者：

| 集 | 前 3 秒钩型 | 15s 小反转 | 主爽点 PAY-N / 类型 | 集尾钩型 | 兑现集 | 卡点位 |
|---|---|---|---|---|---|---|
| N | 直接冲突/强悬念/极致反差 | 有/无 + 内容 | `PAY-###`（8 类之一，五要件齐否） | 七型之一（沿用 `episode-planning.md:289-301`） | `payoff_episode` | 是/否 |

**配额**（外部方案口径，**经验值·非实测**）：重点集 25~35%、卡点位 10~15%（`0xsline`）；单集钩子类型分布须均匀，⛔ 不得连用同一钩型。

### 4.4 「卡点位」在本包的语义转换（★ 必须裁决）

外部方案讲的是**付费墙**（红果/番茄的变现卡点）。本包是**提示词生成系统，不做变现设计**，故：

- 本包把「卡点位」定义为 **强悬念留存位**：即「情绪高点刚过、立刻引入新冲突」的那一集尾，服务的是**追更动力**而非收费；
- ⛔ **禁止**在产物里写「付费」「付费墙」「充值」「解锁」等商业化措辞；
- `sd-recon-engine` 情报卡里的「付费卡点位置｜未找到（需实际观看）」字段（现有三处）**保持原样**，本文件不改采风口径。

## 五、 单集节奏：外部四拍表 vs 本包铁律的折算

外部 `short-drama-factory` 的四拍表（`0~15s` 抓人立事 → `15~45s` 正面交锋 → `45~85s` 亮牌翻转 → `85~110s` 余波钩子）**按 90~120 秒单集设计**，与本包模型契约冲突（见 §六）。本包采用**比例折算**，不写绝对秒：

| 相位 | 占本段比例（经验值） | 本包落法 |
|---|---|---|
| 抓人立事 | 前 ~15% | 黄金前 3 秒钩子在首镜（`SKILL.md` 法则 17） |
| 正面交锋 | ~15%~45% | 台词密度 ≥3.5 字·秒⁻¹ 安全线（**本包实测口径**，法则 20·★） |
| 亮牌翻转 | ~45%~85% | 本集主爽点兑现（五要件齐），完成本集结算 |
| 余波钩子 | 末 ~15% | 集尾钩子；若按 D 锁① 收束，末 1 秒定格仍照 `segment-splicing.md` 执行 |

> ⚠️ **比例不是模板**：`SKILL.md` 法则 20·★「一切节奏规则服务剧情」仍为上位，静场/宣判/留白段可整体偏离，但须标注段落意图。

**强画面三锚点**（外部口径，与本包 C20 具象化铁律同向）：每 2~4 句对白插 1 条强视觉动作（物证亮牌 / 物理结果 / 身份反差忙活），连续纯对白不超 6 行；⛔ 封杀「眼神微动」「推半寸」这类不可渲染的无效微动作。专业术语/设定黑话**当句换算成钱 / 命 / 地位**。

## 九、 剧情衔接逻辑（防跳转 · 2026-11-15 用户裁定）

> **用户原话**：「剧情衔接要更符合逻辑，不能太跳转。」
> **病根**：小说是**叙述流**（可以「三年后」一句话带过），短剧是**因果流**（观众只看得见画面里发生的事）。改编时把叙述改成画面，**原本靠文字说明的因果就断了** → 观众觉得「怎么突然就」。

### 9.1 因果桥五问（每一处场景/时间/人物状态变化，必须能答全）

1. **他想要什么**（本场目标，一句话说得清）；
2. **谁/什么挡着**（阻碍必须是画面里看得见的）；
3. **他做了什么**（具体动作，不是「他决定」）；
4. **结果是什么**（可被镜头拍到的变化）；
5. **下一个动作从哪来**（下一场的第一件事，必须是第 4 条的**直接后果**）。

> 五问里只要有一问答不上 → 这一处就是**跳转**，必须补桥，不许用旁白/字幕硬解释（平台判低质）。

### 9.2 七类跳转病与修法

| 病 | 症状 | 修法 |
|---|---|---|
| **时间跳** | 「三年后」式切换，观众不知过了多久 | 用**可见锚**：换季的树叶/腹部的孕肚/烧到一半的蜡烛 + 一句带时间的台词 |
| **空间跳** | 上一场在室内，下一场突然在街上 | 加**动作承接镜**：起身/推门/上车（1 个镜头即可） |
| **动机跳** | 人物突然同意、突然翻脸 | 补**触发事件**：一句挑衅、一个物件、一条消息；动机必须在**本场或上一场**可见 |
| **信息跳** | 关键信息凭空出现 | 补**信息来源**：谁说的/在哪看到的；⛔ 不许角色「突然知道」 |
| **关系跳** | 陌生人下一场就叫「老公」 | 补**关系建立镜**：一次握手/一次称呼变化/一次共同经历 |
| **情绪跳** | 上一秒崩溃，下一秒大笑 | 补**情绪转轴**：一个动作（深呼吸/擦脸）或一句自我说服 |
| **段缝跳** | 多段拼接处动作对不上 | 按 D 锁做**末帧承接**：上段最后一帧的姿态 = 下段第一帧的起势 |

### 9.3 修法三件套（每次衔接至少用一件）

1. **动作承接**：上一场结束的动作，是下一场开始的第一个动作（关门 → 门内视角）；
2. **台词钩**：一句台词同时交代时间、因果、情绪（「你昨天说的那件事，我答应了」）；
3. **物件/环境锚**：同一件道具、同一种天气、同一段环境声跨场延续。

### 9.4 与既有铁律的接线

- 转场**手法**归 D 锁（`segment-splicing.md` / `creative-transition-library.md`），本文件只管**逻辑是否成立**；
- 每集钩子矩阵（§四）负责「集末留钩」，本文件负责「集内不跳」；
- 分镜层：每场戏的**入场动机**与**出场状态**必须写进分镜表首尾两行，缺行即视为未完成。

## 十、 改编升级：情绪发动机置换（2026-11-16 · 外部方法论归纳 + 自有改进）

> **用户诊断**：「对小说原文转化成短剧剧本还是不太满意」。
> **病根定位**：本包原有七类改编决策偏「**保真 + 删减审计**」——把小说**压缩**成短剧，情绪源仍是原著的。
> 但爆款短剧靠的是**换情绪发动机**：原著只提供人设 / 关系 / 世界设定，爽点节奏由短剧框架重新供给。
> ⚠️ 本节为**方法论归纳**（来源见 §十.5），不含任何外部原文、成稿、参数表；平台节奏数字标「经验值·待核验」。

### 10.1 框架置换术（四步，替代「照着原著删」）

1. **抽资产**：从原著只取三样——人设三层卡、人物关系图谱、世界设定硬约束；**情节顺序不继承**。
2. **选框架**：从爆款框架库选一个「情绪发动机」（逆袭打脸 / 身份揭晓 / 重生改写 / 契约关系 / 悬疑抽丝 / 群像博弈）。
3. **装发动机**：把原著资产塞进新框架，明确「观众每一集为谁憋气、为谁爽」。
4. **重写前 3 集**：按 §10.2 的四拍表从零写，⛔ 不从原著章节顺序平移。

> 判别式：如果改编后「观众爽的时刻」和原著高潮时刻**完全重合** → 只是压缩，没有置换 → 打回。

### 10.2 单集四拍表（每集必填，缺一格写「待验证」）

| 拍 | 时点 | 硬要求 | 类型 |
|---|---|---|---|
| **钩子** | 0~3s | Conflict / 强悬念 / 极致反差 三选一；⛔ 禁环境、心理、起床类铺垫 | 经验值·待核验 |
| **三交代** | 0~10s | 本集核心矛盾 + 人物关系 + 主角目标，三件齐 | 经验值·待核验 |
| **首爽点** | 前 30s | 第一次情绪释放（小反转 / 亮底牌 / 误会解开），形成「压→爆」 | 经验值·待核验 |
| **情绪节点** | 每 20~30s | 台词 / 动作 / 信息冲突至少一处，不许长时间平 | 经验值·待核验 |
| **尾钩** | 结尾 5~10s | 悬念钩 / 危机钩 / 反转钩三选一，力度 > 本集所有冲突 | 经验值·待核验 |

90 秒集的标准配比：**压抑 30s → 转折 30s → 高光打脸 30s + 5s 尾钩**（按时长等比缩放，骨架不变）。

### 10.3 长线布局（六条硬判据，可机检）

| 码 | 判据 |
|---|---|
| **A1** | 第 1 集必须有钩子，且钩子类型已登记 |
| **A2** | 1~5 集完成世界观 / 人设 / 主线矛盾；**第 3 集有一次小爆点** |
| **A3** | 爽点间隔 **≤ 3 集**（空档即补） |
| **A4** | **大爆点不许压在最后一集**（要留释放与收束） |
| **A5** | 三集一次小反转、五集一次大高潮；虐点与爽点交替，禁连续虐主无反击 |
| **A6** | 反击手段限定在**规则框架内**（证据 / 商业博弈 / 举报 / 行业封杀），⛔ 禁私刑与违法报复（平台红线） |

### 10.4 人设三层立体化（治「工具人」）

每个具名角色必须写满三层，缺一层即视为未完成：

- **表层标签**：一句话能认出（身份 / 气质 / 口头禅）
- **深层过往**：解释了「他为什么这样」（伤痕 / 童年 / 一次失败）
- **行为动机**：当前每集要什么、怕什么、底线在哪

⛔ 反派不许只有「坏」：要有贪婪 / 自卑 / 恐惧之类的底层动机。

### 10.5 从外部吸收的三条工程做法（已去原文，只留判据）
