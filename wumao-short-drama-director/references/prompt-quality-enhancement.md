## 一、 八维模型的经验依据

八维来自对**公开成片提示词写法共性**的归纳：**首帧/身份锚定**与**每镜带来新信息**是高质量成片里最稳定的两个特征；而堆分镜编号、堆运镜标签、堆负向约束、堆结构化栏位并不带来更好的结果。这一观察与本包三条老铁律一致：

- 粉色大象法则（否定式禁令禁入，`SKILL.md` §三 法则 19）；
- 一镜一主槽 / 禁堆砌（`expression-motion-prompt-bank.md` §六）；
- 只写画面语言、禁抽象结果词（C25）。

> ⚠️ **诚实标注**：以上均为**经验性观察（经验值·待实测）**，未经本机实拍验证，⛔ 不构成门禁、不写进 C 码、不作为 FAIL 依据。八维是**体检维度不是必填栏位**——缺哪维补哪维，⛔ 不许为凑齐八维把稿子撑爆（见 §四 裁决 1）。

### 1.1 三条最可复用的写法

1. **首帧锚定清单**：首行逐项列出「必须保持不动」的外观 / 服装 / 道具 / 画风，不写笼统的「保持一致」；
2. **每镜唯一新信息**：每个时间戳段只写一个不可逆事件（谁做了什么、画面因此变成什么），⛔ 不用「快速展示」「多个特写」「一系列镜头」；
3. **枚举式节拍骨架**：见 §三，逐条编号、每条一个可读的独立状态。

## 二、 八维质量模型（本文件核心 · 与诊断器 D1~D8 一一对应）

> 每维给：定义 → **中文正向写法**（可直接用） → 反例 → 本包落点。八维是**体检维度不是必填栏位**——缺哪维补哪维，⛔ 不许为了凑齐八维把稿子撑爆（见 §四 裁决 1）。

| 码 | 维 | 中文正向写法（示例） | 反例 / 本包落点 |
|---|---|---|---|
| **D1** | **首帧 / 身份锚定清单** | `首帧精确沿用参考图1，锁定短发、米白衬衫、深棕挎包三项不变。` | ⛔ 笼统「保持一致」「不要变脸」。落 `【场景资产】` + `@CHR_name`；与 `asset-spatial-ledger.md` 五官 10 项 / 服装材质 6 项对齐 |
| **D2** | **每镜唯一新信息** | `[0-4秒]：她推开木门，门轴带动风铃晃了一下。` | ⛔「快速展示多个特写」「一系列镜头」。落 `【时间轴分镜】`；与 `novel-to-shortdrama-adaptation.md` 爽点五要件同构（准备/压制/见证/兑现/后果） |
| **D3** | **时间码 / 节拍骨架** | `[0-4秒]…[4-8秒]…[8-12秒]`，各段累加 = 段总长 | 落 `model-adapters.md:390` 官方 `[起始秒-结束秒]`；**组内不硬切、靠运镜过渡**（见裁决 3） |
| **D4** | **运镜因观看需要而动** | `镜头随她转身缓缓横移，把门后来人带进画面` | ⛔ 句末堆「推镜+拉镜+环绕+手持」。落 `camera-movement-prompt-bank.md` 的 `spec` 中文合法运镜族；**因果句**优先于标签 |
| **D5** | **声音与事件同步** | `图标落地的同时，一声短促下滑音接轻撞击声，随后归于静默` | ⛔ 只写「有背景音乐」。落 `【音效】` 三层电平（`SKILL.md` 法则 9）；**静默也要显式写** |
| **D6** | **物理因果与交互边界** | `裙摆扫过背景，背景像布帘荡开一道横向涟漪；仅左侧三枚图标可被带动，顶栏与底部完全不动` | ⛔ 否定式禁令。**正向锁定**（「仅 X 可动 / Y 保持不动」）＝本包粉色大象法则的合规写法；落 `camera-specs-15rules.md` 物理档 |
| **D7** | **跨切继承 / 段缝承接** | `承接上一镜的视线方向，上一镜留下的倾斜图标在下一镜仍保持倾斜` | 落 `segment-splicing.md` D 锁四选一 + 七类接续锚（动作方向/视线/光线/道具/轮廓/声桥/受力）；与 `prompt-feeding-checklist.md` 第 33 项互锁 |
| **D8** | **收束态与余韵** | `末帧定格在她低头读完信的样子，风铃恢复静止` | ⛔ 动作写到一半就断。落 `blocking-direction.md` 节拍闭环「起始姿态→过程→收势」 |

**三条反模式（诊断器 A1~A3，命中只提醒、不判错）**：A1 否定式禁令堆砌 → 改正向锁定；A2 笼统批量展示词 → 改枚举式节拍（§三）；A3 抽象情绪结果词 → 改 FACS 器官动作。诊断器另有 **A4**：单行出现 ≥3 个运镜词 → 改一句因果式运镜。

## 三、 枚举式节拍骨架（高赞样本里最可迁移的结构）

Top3（♥1338，@aimikoda）用 `exactly 10 distinct fashion poses, each with a different silhouette and camera angle` 逐条编号；同类还有 `anime-character-reveal-trailer-in-13-beats`、`beat-synced-character-showcase-across-five-environments`。归纳出**可复用的中文模板**：

```
【节拍骨架】共 <N> 拍，每拍一个可读的独立状态，⛔ 不重复、不追加：
 1. <状态/姿态/景别/机位> —— 本拍带来的新信息：<…>
 2. …
 N. <收束拍> —— 最终状态 + 余韵
拍间衔接：<动作匹配 /  whip pan / 遮挡 / 光线接续 / 声桥>，加速到倒数第二拍，末拍急停。
节奏契约：<BPM / 每拍时长 / 何时加速、何时刹住>
```

**三条纪律**（从样本反推，与本包铁律一致）：
1. **每拍一个「可读的独立状态」**，不是「多个镜头快速闪过」——这正是 A2 笼统词的解药；
2. **拍间必须写明衔接物**，不能靠「然后」硬跳（D7）；
3. **节奏要写成可执行的数**（BPM / 每拍秒数 / 加速与刹停点），不是「节奏紧凑」——与 `dialogue-speed-check.md` 台词密度 ≥3.5 字·秒⁻¹ 同源。

> ⚠️ **配额**：N 由内容倒推（`SKILL.md` 法则 17），⛔ 不得为凑「13 拍」拉伸凑满（C15）。本包 2.5 单段 ≤30s / 2.0 ≤15s，节拍数须落在模型时长契约内。

## 六、 迭代法：两次同缺陷，改结构不换随机种子

归纳自本机 `comfyui-h3-local-runner/SKILL.md:47-53` 与 `director-playbook.md:93-106`（与本仓库样本互为印证），作为**质量层的重试纪律**：

1. **只重生成失败的那一拍/那一段**，不整段重来（`selective recovery`）；
2. **同一缺陷连续出现 2 次** → 必须改 **镜头结构 / 参考锚策略 / 正向锁定措辞**，⛔ **不许只换 seed 再抽一次**（换 seed 只改噪声，不改结构缺陷）；
3. 重生成前用八维体检定位是哪一维缺（多数是 D1 锚定或 D6 交互边界），补完再提交；
4. 记录「缺陷 → 改了哪一维 → 结果」，进 `quality-gate-review.md` 三步复验。

## 七、 使用与自检

```bash
python3 scripts/prompt_quality_audit.py feed.md          # 八维体检（只建议）
python3 scripts/prompt_quality_audit.py feed.md --json   # 机读结果，便于接流水线
python3 scripts/prompt_quality_audit.py --corpus         # 看语料复算统计
python3 scripts/prompt_quality_audit.py --self-test      # 自测
```

**出稿前自检**：

- [ ] `validate_prompt.py` 的 C 码 **FAIL 清零**（合规层，先过这道）；
- [ ] 跑过 `prompt_quality_audit.py`，八维**看建议而非凑分数**——缺的维度确实需要才补，⛔ 不为凑齐而扩写；
- [ ] 反模式 A1~A4 已检查：无否定式禁令堆砌、无笼统批量词、无抽象情绪词、无单行运镜标签堆砌；
- [ ] 若用了枚举式节拍骨架，N 由内容倒推、累加时长与模型契约一致、拍间衔接物写明；
- [ ] 六条冲突裁决未绕过：无英文字段名、无硬切语法、无 `constraints:` 负向块、无 H3 参数/锚点语法、无成稿全文；
- [ ] 质量层建议**由编导人确认后**才落稿，⛔ 不把诊断结果当自动改写指令。
