# H3 出片实战排坑：音轨、格式与规模化 QC（2026-11-23/24 实跑回写）

> **定位**：`h3-adapter.md` 管「提示词格式权威」，本文管**「跑起来之后踩的坑」**——音轨污染、段长策略、QC 缺口、规模化编排。两文配套。
> **来源**：末日求生短剧项目 E01~E10 全量出片实证（246 段 / 233 句台词 / 约 21 分钟成片）。所有结论有 ASR 转写或抽帧铁证，非估算。
> **触发**：E01 v1/v2、E02 v1/v2 曾两次交付有问题的成片被用户复核发现，第三轮全量重做才彻底修复。本文是把代价高昂的教训固化成规则。

---

## 〇、一句话总纲（先读这条）

> **H3 出片的头号风险不是画面，是音轨。** 模型会把 prompt 里任何中文文字当台词念出来；QC 若只查画面/台词命中，必然漏检。**六段英文 + 逐段 ASR 复检 = 两个不可省的闸门。**

---

## 坑 A · 中文 prompt / 中文工程指令 → 模型把提示词念成台词（最严重）

### 现象（用户复核发现：「音频有问题，怎么把提示词都说出来了」）

ASR 逐段转写铁证（旧版音轨实际念出的内容）：

| 段 | 旧版念出的 |
|---|---|
| 某短台词段 | 「可惜了，**青金说到到底不欠您不加花式运镜**」|
| 某无台词段 | 「**切胜飞鸥祝祝为样稿，咸却朝羹主胜洽自纣**」（整段乱码）|
| 某段 | 「结束了，**5.17 秒，单镜到底，不切镜，不加花式运镜**」|
| 系统播报段 | 「…**每句说完留自然气口与停顿**…是否收留」|

一句话台词段能蒙混过关（台词长，把描述挤掉了），**短台词段和无台词段必翻车**。

### 根因

写 prompt 时犯了两条：
1. **整段用中文写**（场景、人物、动作、禁项全是中文）——H3 官方要求六段全英文，只有 `<d>` 内台词保留原语言（`h3-adapter.md` §4.0 已有此规则，但旧版没执行）。
2. **塞了中文工程指令**：「5.17 秒单镜到底，不切镜，不加花式运镜」「每句说完留自然气口与停顿」——模型分不清描述与台词，把整段中文当 TTS 文本念出来，念成乱码。

### 修复（已验证：33 段重做后 ASR 全干净）

全量改为官方六段式 + 数据驱动生成：
- `subject_definitions` / `summary` / `retention_analysis` / `detailed_description` / `overall_soundscape` / `non_diegetic_music` **六段全英文**
- 说话人稳定 ID `(S1)/(S2)/(S3)…` 写在 `<d>` **外**：`<Subject 1> (S1) says: <d>[Chinese] 台词。</d>`
- 画外音：`says in an off-screen voiceover: <d>…</d> while … lips remain completely closed`（系统无实体，不写 lips 声明）
- **无台词段不写任何 `<d>`**，只写英文画面 + 环境声
- **绝不写中文工程指令**；要表达"别念多遍"用英文写进 detailed_description 自然句，或不写

### 自检闸门（提交前必跑）

```python
# 非台词中文行必须为 0
def validate(prompt):
    errs = []
    for ln in prompt.split("\n"):
        if any("\u4e00" <= c <= "\u9fff" for c in ln) and "<d>" not in ln:
            errs.append("非台词中文行: " + ln[:60])
    return errs
```

**铁律**：`validate(prompt)` 返回非空 → 禁止提交。这条闸门能 100% 拦住本坑。

## 坑 B · ContextWindows 长段 → 台词/画面重复（推翻 h3-adapter 坑4 的推荐配方）

### 现象

用户复核：「视频里很多重复的语音和视频」。音频 RMS 铁证：v1 正式段 1 全程 12 秒音量 73–79 dB **零停顿**，本该环境音的 2.5s 仍有 76.9 dB 人声；抽帧看到同一段「门开了三次」。

### 根因

`MiniMaxH3ContextWindows`（overlap-linear + 6 步）虽消除了网格伪影，但**让台词在重叠窗口里反复生成**——同一句念 2-3 遍、同一动作执行多次。原 `h3-adapter.md` 坑4 把它当"稳定配方"推荐，是错的；已在该文件加重大修正说明。

### 修复（现行唯一推荐路线）

**5 秒段 + 无 ContextWindows + 出片后超分**：

| 参数 | 值 |
|---|---|
| 段长 | 124 帧 ≈ 5.17 秒 |
| 分辨率 | 480×864 出片 → lanczos 超分 720×1280 |
| steps | 4 |
| ContextWindows | **不挂** |
| 单段耗时 | 60-80 秒（偶有 270-400 秒慢段，仍成功）|

每段 1-2 句台词；3 句塞不下会乱念。段缝靠 ASS 后期字幕与画面连续性（参考图锁身份）解决，不靠窗口硬接。

**代价**：段数多（246 段），但每段快、可并行 CPU 交付、失败只重出一段。**收益**：零重复、零网格伪影、显存需求低（1.4 GB 也能跑）。

## 坑 C · QC 只查「台词命中」不够——必须逐段 ASR 复检「音轨只有台词」

### 现象（两次漏检）

- v1 QC 查了：ASR 台词命中 ✅ / 无伪影 ✅ / 字幕位置 ✅ → 判定通过。
- 用户复核：音轨在念提示词、台词被重复念。**命中 ≠ 没多念**。

更糟的是我曾用一个错误判据：「-35 dB 以下静音窗 < 2 个 = 疑似重复」——结果对有持续环境音的 5 秒段**全部误报**（连用户已认可的干净基准片也是 0 静音窗）。RMS 停顿检查对 H3 原生音轨不适用。

### 修复：ASR 内容检查（唯一可靠判据）

每段出片后用语音转写工具（如 `AudioTranscribe`）转成文字，逐段核对：

| 段类型 | 合格音轨 |
|---|---|
| 有台词段 | 转写文本 = 台词（可含合理 ASR 谐音误差），**无任何中文指令/描述词** |
| 无台词段 | 转写为空（仅环境声）|
| 系统播报段 | 只有系统台词，无角色多余口型声 |

**规模化抽检策略**（8 集 213 段全量转写不现实）：格式闸门 `validate=0` 已覆盖全段，ASR 抽检每集 3-5 段（优先无台词段、系统播报段、短台词段）即可。

### 配套：画面 QC 看时间轴网格

每 5-6 秒抽一帧拼 tile（如 `fps=1/6,scale=120:213,tile=6x4`），一次通看整集：场景是否推进、有无整段回跳/重复播放、角色脸服装是否跨段一致、有无幽灵人/网格伪影。比逐段抽中间帧可靠。

## 坑 D · 从四格设定板裁角色身份锚点（不能整板投喂）

### 现象

直接把角色的四格立绘板喂给 H3 → 出四格排版、幽灵人、脸漂移。`h3-adapter.md` 坑5 已警告"设定板不能当 ref_image"，但没给裁切方法。

### 修复：裁 3 张身份锚点

每角色从四格板裁 `full` / `head_shoulder` / `half` 三张到 `refs/anchors/<角色>/`：

1. 用 PIL 找第 2 格（正面全身像）的非白包围盒定位人物；
2. 头肩 = 人物中心 ±95px、头部 y 区间；全身 = 包围盒全高；半身 = 上半 60%；
3. **第 1 格头肩构图偏上会切下巴**——改用第 2 格全身像的头部区域裁头肩；
4. 裁完必须目视验证脸完整、非白比例 35-59%（防止裁到白边）。

双人或三人同框段按出场角色挂图：每角色 3 张，按 roles 顺序编号 `<Picture 1..N>`，**最多 3 角色 = 9 张**（H3 上限）。参考图只锁身份服装，场景靠英文 prompt 文字写死，不挂场景图（挂图多了出幽灵人）。

## 坑 E · ASS 长台词不拆行 → 溢出被裁字

### 现象

首版 30 字台词单行渲染，首个字被裁掉（"靠腿赶路"的"靠"没了）。

### 根因与修复

本机 libass 的 `WrapStyle=2` 不自动折行。必须手动拆：

```python
def wrap_text(text, max_chars=16):
    if len(text) <= max_chars: return text
    for i in range(len(text)-1, max_chars//2, -1):
        if text[i-1] in "，。！？……、；：":
            return text[:i] + "\\N" + text[i:]
    mid = len(text)//2
    return text[:mid] + "\\N" + text[mid:]
```

配套：字号 36、`MarginV=150`、`Alignment=2`（底部居中）、`PlayResX/Y=720/1280`。长句拆两行后底部安全区完整显示、不遮主体。

## 坑 F · 规模化出片：数据驱动 + 闸门脚本 + 无人值守编排

8 集 213 段、连续 3 小时跑完，靠的不是逐段手搓，是三层结构：

### 1. 数据驱动 prompt 引擎（一致性根基）

- `h3_shared_defs.py`：角色英文外观 + Voice Lock + 场景 key 集中定义，跨集一致。
- `h3_prompt_engine.py`：`build_prompt(cfg)` 生成六段式 + `validate()` 闸门。
- 每集只需一份 `eNN_shorts.py` 段数据（英文画面 + 中文台词 + roles），prompt 由引擎统一生成。

**规模化的核心**：格式一致性靠引擎保证，不靠每个 agent/人自觉。全局校验段号连续、台词逐字覆盖、每段 ≤2 句、`validate=0`。

### 2. 试片闸门（先试片再放量）

新集/新角色/新格式，先跑 1 段试片（优先选新角色出场段），双重验证：ASR 音轨干净 + 抽帧脸稳无幽灵人，通过后再全量铺开。这是资源纪律，也是质量保险。

### 3. 无人值守编排

`run_remaining_episodes.sh` 顺序跑多集：每集出片（GPU 串行）→ 交付（CPU 超分+拼接+字幕）→ 下一集。单段失败即停（不静默吞错）。出片与交付分离让 GPU 不空等 CPU。

**代价记录**（不编数字）：本机 4080 16G，5 秒段 60-80 秒/段，打戏段偶有 270-400 秒；8 集 213 段约 3 小时 12 分。显存低至 1.4 GB 时 5 秒段仍能跑（12 秒段需 >5 GB）。

## 七、出片前 / 后检查清单（直接照跑）

**提交前**
- [ ] `validate(prompt)` 全段返回空（无非台词中文行、六段齐全）
- [ ] 无台词段未写 `<d>`
- [ ] 每段 ≤2 句台词、台词逐字照抄分镜稿
- [ ] 新角色锚点已裁 + 目视验证（脸完整、非白 35-59%）
- [ ] 每段 roles ≤3（≤9 张图）

**出片后**
- [ ] 每集抽检 3-5 段 ASR：有台词段只有台词、无台词段空音轨、无工程指令被念
- [ ] 每集时间轴网格通看：场景推进、无回跳重复、脸服装一致、无幽灵人/网格伪影
- [ ] 字幕帧：长句已拆行、底部安全区不裁切
- [ ] 规格：720×1280 / h264+aac / 时长与段数匹配

- **画面内 UI 文字**：系统/序列面板镜有模型生成的界面文字与数字（如 E03 序列选择、E10 面板播报），属场景固有 UI，同 E01 公里牌豁免。平台严格时后期遮盖或贴真实 UI。
