# 技能自成长协议（吸收 · 判断 · 修改 · 淘汰 · 双轨开源）

> **定位**：本包不是资料夹。外部的好点子要变成**判据**，不是变成一段摘抄。
> **最高原则（用户 2026-11-16 裁定）**：「不是简单的收集，而是不断的自我判断、自我修改、自我成长；随时能开源或闭源，不能有法律风险。」

---

## 一、六步闭环（缺一步不算吸收完成）

```
① 发现  →  ② 去原文摘要  →  ③ 冲突裁决  →  ④ 判据化  →  ⑤ 回归验证  →  ⑥ 留痕 / 复审 / 淘汰
```

| 步 | 动作 | 产出 | 不通过怎么办 |
|---|---|---|---|
| ① 发现 | 扫 GitHub / 平台方法论 / 自己实跑的教训 | 候选卡（脚本生成） | — |
| ② 去原文 | **只写「做法 + 为什么有效 + 适用边界」**，⛔ 不贴原文、成稿、提示词全文、图片、真人信息 | 抽象描述 ≤ 300 字 | 触发原文检测 → 打回重写 |
| ③ 冲突裁决 | 对照本包现有权威表，问「归谁管 / 有没有推翻旧判据 / 是否制造第二套口径」 | 裁决记录（沿用 / 覆盖 / 拒绝） | 有冲突但不愿改旧判据 → 拒收 |
| ④ 判据化 | 必须落成**可检查的东西**：一句硬规则、一个脚本断言、一个表格字段、一个门禁码 | 规则 or 代码 | 只能写成「要注意…」→ 拒收（那是废话） |
| ⑤ 回归验证 | 运行 `scripts/check_package.py` 与改动域的现存回归；脚本不存在时先修正文档引用，不虚报已执行。涉及生成执行链的改动另补实际验证，纯文档整理不触发生成 | 实际检查结果与未验证边界 | 有 FAIL → 修复或回退本次改动，不算完成 |
| ⑥ 留痕 / 淘汰 | CHANGELOG 一行、版本号进位、登记触发条件；连续两轮未被触发或被新证据推翻 → `deprecated` → 移出必读 | 版本记录 | — |

## 二、吸收评分卡（5 问，任一不过就不收）

1. **增量**：它比本包现有做法好在哪？说不出具体增量 → 拒。
2. **归属**：归哪个规则域？找不到唯一权威 → 先补归属再谈。
3. **可验**：能不能被脚本或一条硬判据检查？不能 → 降级为「参考」，不进规则库。
4. **冲突**：会不会与本包铁律（锁系统 / 七段式 / C 码 / 素材形态 / 画风锁）打架？打架要有明确裁决，不能两套并存。
5. **回退**：改坏了怎么退回？必须有备份点与 package 版本号。

`scripts/absorb_candidate.py` 把这 5 问做成结构化卡片和自动初筛，**它只产候选，不自动改规则**——最终裁决由使用者拍板。

## 三、法律边界（开源 / 闭源双轨）

### 3.1 三层内容

| 层 | 内容 | 许可 | 开源包 |
|---|---|---|---|
| **核心层** | 本包自撰规则、脚本、表格、自撰提示词 | MIT | ✅ 进 zip |
| **吸收层** | 从外部**抽象出的方法论与判据**（无原文） | 自撰，MIT；来源按许可要求记入 NOTICE | ✅ 进 zip |
| **私有层** | 用户自有素材、未公开数据、商业策略、含来源痕迹的草稿 | 不授权 | ⛔ 不进 zip |

### 3.2 许可兼容矩阵（抽取方法论时的硬规则）

| 来源许可 | 可做什么 | 禁止什么 |
|---|---|---|
| MIT / Apache-2.0 / BSD | 抽方法论、写进自撰规则；Apache-2.0 需在 NOTICE 注明 | 复制代码/文档原文；去掉原许可声明 |
| CC BY 4.0 | 抽统计与方法论，署名 + 链接 | 复制成稿全文 |
| **NOASSERTION / 未标许可 / 全权保留** | **只做思路观察**，写「行业通行做法」 | ⛔ 落盘任何具体条目、参数、文案、来源名 |
| GPL / AGPL / SSPL 类 | 只做远距离观察 | ⛔ 抽取任何实现细节（避免许可传染） |
| 付费 / 内部分享 / 未授权小说 | 一律不收 | 一切 |

> 实测案例（2026-11-16）：`waoowaoo` star 14,867 但 `license=NOASSERTION` → 只当行业思路看，**不落任何具体条目**；`shuohao-skills` Apache-2.0、`ViMax` MIT → 可抽象其「分镜只做输出不做新决定」「质量门脚本化」等方法论。

### 3.3 双轨切换（一键）

- **开源态**：仓库根 `LICENSE` = MIT；`NOTICE.md` / `THIRD_PARTY_NOTICES.md` 声明「不含第三方内容」；`zip` 打包排除 `private/`、`00_source/`、`.git/`、`__pycache__/`、`*.bak`。
- **闭源态**：把商业/私有内容放 `private/`，`.gitignore` 已排除；核心层保持 MIT 不动，**随时可闭源而不必重写历史**。
- ⛔ **不要把来源 URL、账号、真人姓名、作品名、star 数写进对外交付的规则正文**（可写进 CHANGELOG 的方法论备注，且中性化）。
- ⛔ 不收录：小说原文、公众号逐字稿、第三方提示词成稿、真人照片/肖像、明星脸、真实品牌商标。

## 四、自我修改与淘汰

- **触发式复审**：每次 `absorb_candidate.py` 新增候选时，扫描现有规则里标记 `deprecated` 的条目，输出「可清理清单」。
- **淘汰三条**：① 连续两轮真实任务未触发；② 与新增判据冲突且新判据更优；③ 实跑证明无效。
- **动作**：从「强制读取清单 / 按需台账」移除 → 移入 CHANGELOG 归档 → 版本号进位 → 包检全绿。⛔ 不静默删除（保留沿革）。
- **版本号**：吸收 = patch；新增规则域 = minor；架构变更 = major。当前版本以 `SKILL.md` frontmatter 与 `README.md` 为准，不在本文件另立版本常量。
